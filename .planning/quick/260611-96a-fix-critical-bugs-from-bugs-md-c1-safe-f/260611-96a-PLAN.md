**C4 — reorder `monitor_positions` in `agents/agent_i6.py` (lines 117–123) so hard exits always run.** Currently the `circuit_set` skip and `_check_circuit` run BEFORE the SL/target checks, and circuit membership is permanent — a flagged position is never exit-managed again. 1. Resolve current price (unchanged).
2. Hard exit: stop loss (move the existing `current_price <= pos["stop_loss"]` block here, unchanged).
3. Hard exit: target (move the existing `current_price >= pos["target"]` block here, unchanged).
4. Circuit recovery: if `sym in circuit_set` and the new price differs from the last recorded price in `self._price_history[sym]` (deque exists and `current_price != d[-1]`), call `circuit_set.discard(sym)` and `logger.info("Circuit recovered for %s — price moving again", sym)`. Do this BEFORE appending the new price.
5. Circuit detection: call `self._check_circuit(sym, current_price, circuit_set)`; if it returns True, OR if `sym` is still in `circuit_set` after the recovery check, `continue` (skip partial-exit and trailing-SL logic only — hard exits in steps 2–3 already ran).
6. Partial exit and trailing SL logic (unchanged, stays last).

Keep `_check_circuit` itself unchanged (append + 3-identical detection + notifier). The recovery logic lives in `monitor_positions` before the append so the deque comparison uses the previous cycle's price. Update the module docstring bullet order if it mentions circuit-before-exits.

**C5 — extract daily reset in `execution/portfolio.py` into a public method called from every trading path.** `_restore_state` (lines 165–190) only runs at `__init__`, so a service running continuously across days never resets `daily_pnl`/`trade_count`/`is_halted`/`force_squaredoff`. Fix:

1. Extract the daily-reset block of `_restore_state` (the `today = ...` / `last_date = ...` comparison and all the `_set_meta` resets + watchlist DELETE + log line) into a new public method `reset_daily_state_if_new_day(self) -> None` with a docstring noting it is a cheap guard (one meta read) that only acts when `last_trade_date != today`. `_restore_state` keeps the seed-defaults block and then calls `self.reset_daily_state_if_new_day()`.
2. Call `self.reset_daily_state_if_new_day()` as the FIRST statement in `buy()`, `sell()`, and `force_squareoff_all()`. In `force_squareoff_all` it must run BEFORE the `force_squaredoff == "1"` idempotency check — that stale day-1 flag no-oping day-2 squareoff is the core C5 bug.
3. In `execution/scheduler.py` `run_pre_market_pipeline`, call `self._portfolio.reset_daily_state_if_new_day()` immediately after the `is_trading_day` guard (before the pipeline runs). With it, `last_trade_date` is already today by the time `buy()` runs, so the buy-path guard no-ops.

**C6 — fix the mid-session restart deadlock in `execution/scheduler.py` `run_market_session` (line ~224).** `_watchlist_ready` is only set by the 08:30 pre-market job; after a post-08:30 restart, `AgentI4.run()` waits on it forever and (with `max_workers=1`) also blocks the 15:35 post-market job. ```

    logger.info("Watchlist ready event not set (restart after pre-market) — setting from restored state")
    self._watchlist_ready.set()
```

This is safe: the `market_session` job only fires 09:15–15:15, after the pre-market window, so the event being unset here always means a restart.

**C7 — stop fake liquidation on shutdown in `main.py` (line ~113).** Graceful shutdown calls `force_squareoff_all({})`, which fills every position at `entry_price` (fictional P&L) AND sets `force_squaredoff=1` (skipping the legitimate 15:15 squareoff if the service comes back).             "Shutdown with %d open position(s) left in DB: %s — "
            "they will be reconciled on restart or squared off at 15:15.",
            len(open_positions), symbols,

except Exception as e:
    logger.error("Error reading open positions during shutdown: %s", e)
```

Do NOT call `force_squareoff_all` and do NOT touch the `force_squaredoff` meta flag from the shutdown path. Update the preceding "closing open positions" log line accordingly (it is replaced by the new block above).
